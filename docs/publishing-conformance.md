This matrix is for Willie and maintainers releasing willie.page. Resolve every applicable pending external check before calling a release fully interoperable. Record successful writes and subscriber receipt separately from HTTP acceptance and simulated behavior.

The baseline was inspected on October 7, 2026. The site is a publisher with response display. Microsub, a reader, a hosted PDS, relays, and ActivityPub delivery are outside this contract. Existing authored drafts remain private.

## Release evidence

A follow-up inspection found an unresolved implementation gap in [Micropub bidirectional text](https://micropub.spec.indieweb.org/#bidirectional-text). The current Micropub baseline is the July 25, 2020 living standard. Its changes from the 2017 recommendation are non-normative, but the direction requirement already applied. Passing unit tests does not close this gap.

On October 7, 2026, the feature branch passed 809 unit tests, ESLint and TypeScript. Acceptance migrations 006, 007 and 008 applied successfully to the separate Neon database. Five existing OAuth/database integration checks passed against that database and removed their temporary rows. Local PostgreSQL separately proved refresh-family rotation/replay and Micropub restoration/concurrency. These checks do not prove external account authorization or interoperability.

The bounded production build passes with two workers. Two browser checks pass, including 19 subscription states captured in both themes at 1440px and 390px. A separate rendering run covers 15 recommendation states at the same sizes and themes. Four full-page response-format captures prove containment, WAV/WebM playback, and absent autoplay. These 140 captures use local model/provider fixtures and do not prove real external responses or account writes.

Fourteen HTTP checks pass against the isolated production build. One tag fixture case was unavailable in that build. The checks cover discovery, Microformats, feeds, unauthorized requests, native Share, and IndieWeb reply controls. A runtime HTTP check against the separate acceptance database proves code redemption, scoped UserInfo, draft creation, nested source/edit round trips, exact delete/undelete restoration, collision rejection, refresh narrowing, escalation rejection, and family revocation on replay. That check seeds its authorization code and does not prove interactive consent or an independent client. It removed every temporary source, archive, code, token and refresh family.

The production owner PDS returned zero Standard.site document records on October 7, 2026. No acceptance writing exists in the production source checkout. Independent validator results, hosted acceptance lifecycle, actual provider grants, real PDS writes, actual response import, subscriber receipt and production rollout remain release gates. Production currently has four authored drafts. Production document/recommendation verification waits for an approved real publication; isolated acceptance must prove those behaviors first.

The available Bluesky browser session contained only the production owner. The setup script `scripts/publishing-acceptance-setup.mts` refuses that DID and configures only the acceptance project. A separate account and its publishing credential are still required. The script also opens the Micropub Rocks and WebSub Rocks sign-in pages for the user to finish with their existing passkey or email. Browser automation currently cannot access the Standard.site validator because its security check cannot verify the administrator policy; no validator result is claimed. No test post may use the owner's PDS.
